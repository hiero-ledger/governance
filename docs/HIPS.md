# HIP Implementation Status

This document provides a central overview of HIP implementation progress across the Hiero ecosystem.

HIPs (Hiero Improvement Proposals) describe proposed changes, new functionality, standards, and design decisions for the Hiero codebase. This tracker provides a high-level view of implementation status across repositories.

For implementation details, please refer to the relevant repository documentation and pull requests.

## Status Definitions

## Status Definitions

| Status | Description |
|--------|-------------|
| Idea | A HIP idea is created and discussed amongst developers. |
| Draft | The HIP has been formally written and is open as a PR in GitHub. |
| Review | The HIP is undergoing formal review and feedback prior to a decision. |
| Last Call | The HIP is in its final review period before being accepted or rejected. |
| Approval | The HIP has been accepted and approved by the TSC. |
| Final Status | The HIP has reached its final outcome (for example, Accepted, Rejected, Withdrawn, or Superseded). |

## Updating This Document

When a HIP implementation is completed:

1. The implementing repository maintainer opens a pull request updating this tracker.
2. The PR should include:

   * HIP number
   * Implementation repository/repositories
   * Current status
   * Links to relevant implementation PRs or releases
   * Any limitations or follow-up work

This document tracks ecosystem-level implementation status. Individual repositories remain responsible for maintaining detailed implementation documentation.

## Updating HIP Implementation Status

When implementing a HIP, maintainers should update the central HIP implementation tracker once the implementation is merged.

The update should be submitted as a separate documentation pull request containing:

* HIP number and title
* Current implementation status
* Repository containing the implementation
* Links to implementation pull requests or releases
* Additional notes where relevant

The purpose of this process is to maintain a reliable ecosystem-wide view of HIP adoption while allowing individual repositories to manage their own implementation details.
