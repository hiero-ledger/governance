# Team

This document records what [PROJECT_NAME] expects of a Contributor before they are nominated for a role.
The categories themselves, and what counts as evidence in each, are defined in the Hiero [Advancement Qualifications](https://github.com/hiero-ledger/governance/blob/main/roles/advancement-qualifications.md).

For the people who currently hold each role, see [MAINTAINERS.md](./MAINTAINERS.md).

## Getting involved

Every activity these thresholds count is open to any developer, with no role and no approval required.
Anyone may open an issue, open a pull request, review someone else's pull request, triage an issue in a comment, and help another contributor and join community calls or participate in activities.

## Difficulty levels

The thresholds below refer to difficulty levels. This project defines them as follows.

Difficulty is applied by an existing Committer or Maintainer during triage, before the issue is assigned. Self-applied difficulty is not used as evidence.

| Level | What it means in this project | Label |
| --- | --- | --- |
| Good First Issue |  *e.g. a narrow, fully guided issue reserved for a first-time contributor* | [ ] |
| Beginner | *e.g. a self-contained change in one file, with an existing test to copy* | [ ] |
| Intermediate | *e.g. a change spanning several modules, requiring new tests* | [ ] |
| Advanced | *e.g. a change to core or cross-cutting behaviour, or one affecting the public API* | [ ] |
